## 2 机器学习的常见的学习方式

### 2.1 监督学习（Supervised Learning）

监督学习是机器学习中**最常用、最直接**的一种范式：

给定一组**输入–输出成对**的标注样本 $(x_1, y_1), (x_2, y_2), \dots, (x_n, y_n)$
目标是让模型学会一个映射函数 $f: x \mapsto y$
使得对新输入 $x_{\text{new}}$ 能尽可能准确地预测出对应的输出 $y_{\text{new}}$。

监督学习是有**“标准答案”**的，每个样本的输出 $y$ 都是人工或可靠系统事先标注好的。 并且**损失可计算**，利用预测值 $\hat{y}$ 与真值 $y$ 之间的误差（交叉熵、MSE 等）可直接作为优化信号。有监督的**目标明确**，最小化训练集上的预测误差，同时兼顾泛化能力（防止过拟合）。

**典型任务**常见的有**分类任务**（离散标签），比如图像识别：输入图片 a-> 输出 “猫 / 狗 / 车”；**回归任务**（连续值），比如房价预测：输入房屋特征 -> 输出价格，等等。有监督学习就是“老师把答案写在卷子上”，模型通过对比自己的答案和标准答案不断纠正错误（通过一些算法，比如梯度下降），从而学会对新题目给出正确结果。它的数据集是有**标准答案**的，标准答案就是一个**监督信号**，所以叫做有监督学习。

---

### 2.2 无监督学习（Unsupervised Learning）

**没有“标准答案”、只有“原材料”即原始数据**，算法的目标不是预测某个具体标签，而是**从数据本身里挖掘出隐藏的结构或分布特征**。

有监督学习的输入为 $(x_1, y_1), (x_2, y_2), \dots, (x_n, y_n)$，它是有标签的。比如说实现一个猫图识别，判断图片是否是猫，是则输出 1，不是则输出 0，0 和 1 就是标签，$y$ 就是标签。而无监督学习没有标签。

**只给输入 x，不给输出 y**，让机器自己找规律、找相似、找低维表示或生成新样本。常见的无监督任务就有**聚类（Clustering）** 把相似样本自动分到一组。  无监督学习就是**不给答案、只给卷子**，让机器自己把题目分堆、找规律、画重点，甚至还能照猫画虎出一份新卷子。

**自监督学习**（Self-supervised Learning）是无监督学习的一个子集，它**把“没有标签”的原始数据自己生成伪标签**，然后再按“有监督”的方式去训练。因此它既属于无监督大家庭，又带上了“假装有监督”的味道。比如说大模型的预训练，还有 BERT 的 **Masked Language Modeling**，以及对比学习等等。

无监督学习的优点就是它**不需要标注，无需昂贵标注，数据拿来就能用；常作为预训练或探索工具**。在机器学习或者说深度学习中有标签的数据一直都是一个难题，它们往往都需要昂贵的人工标注，但是无监督学习能帮工程师省下标注的费用，当然不是所有的任务都能使用无监督的。还得回到具体，实事求是。

---

### 2.3 强化学习（Reinforcement Learning）

强化学习比较复杂，我们会在下一章中详细介绍。强化学习是用延迟、稀疏的奖励信号，让智能体在序列决策中通过试错+价值估计，自己摸索出长期最赚的行动策略。如果说有监督学习是老师给每题标准答案，无监督学习就是没老师，自己找结构和规律，强化学习就是老师只期末给总评（奖励），学生全程自己摸索哪一步对哪一步错。

## 3 大模型训练的第一个阶段：预训练（Pre-training，PT）

2018 年，OpenAI 的 [GPT-1](https://cdn.openai.com/research-covers/language-unsupervised/language_understanding_paper.pdf) 让“预训练 + 下游微调”这一范式真正流行起来。它先在约 5 GB 的 BooksCorpus（约 7000 本书）上用**自回归语言模型目标**做无监督预训练，再在少量标注数据上微调具体任务，从而显著超越当时只能从头训练的模型。需要说明的是，把预训练用于下游任务并非 GPT-1 首创：[ULMFiT](https://arxiv.org/abs/1801.06146) 更早系统提出了“预训练 + 微调”的流程，[ELMo](https://arxiv.org/abs/1802.05365) 也使用了预训练表示；GPT-1 的贡献主要在于把这一思路扩展到完整的 Transformer 生成式模型，并展示了规模化预训练的潜力。

**大模型的预训练**（Pre-training）是让模型先在海量无标注数据上“自学”通用知识，得到一个强大的底座，然后再用少量标注数据去微调解决具体任务。它本质上是迁移学习的极端放大版：把“从数据里学通用表示”这一步做到极致。

在此之前，NLP 的预训练大多停留在词向量或任务特定表示上，还没有“先训练一个通用语言模型、再微调下游任务”的成熟范式，每个模型都要耗费大量时间和人力去收集训练数据。而**预训练 + 特定任务微调**的思路在图像领域更早成为标准做法：先在 **ImageNet** 上预训练骨干网络，再用**小批量标注数据**迁移到下游任务，往往只需要**少量数据**就能得到不错的模型。受此启发，语言模型也可以先在海量无标注文本上训练**一个预训练模型**，再以远比之前少的数据适配各种下游任务。

### 3.1 大模型预训练的范式

当前主流大模型大多采用 **decoder-only** 结构（也有 [T5](https://arxiv.org/abs/1910.10683) 这类 encoder-decoder 模型），其**预训练范式**是不断预测下一个 token，即 **next-token 预测**。最终训练得到一个续写模型，能根据输入不断续写，此时大模型已经通过预训练获取到了许多先验知识。

模型的输入（input）和标签（label）共同用于训练模型预测下一个词或字符。

预训练的**目标序列**是一串字符串，对于输入序列 $[x_1, x_2, \dots, x_{t-1}]$，目标（标签）是序列中的下一个词 $x_t$。**模型的目标**是学习如何根据输入序列 $[x_1, x_2, \dots, x_{t-1}]$ 准确地预测出下一个词 $x_t$ 的概率分布 $P(x_t | x_1, x_2, \dots, x_{t-1})$。

假设我们有一个文本序列：

```markdown
"自然语言处理是人工智能的一个重要分支"
```

我们将这个序列分词后，用长度为 4 的滑动窗口构造训练样本：前 3 个 token 作为输入，第 4 个 token 作为预测标签（这里假设已经完成分词，实际还需要先训练分词器）。

输入和标签的对应关系：

**输入序列**：`["自然", "语言", "处理"]`
**预测标签**：`"是"`

**输入序列**：`["语言", "处理", "是"]`
**预测标签**：`"人工智能"`

**输入序列**：`["处理", "是", "人工智能"]`
**标签**：`"的一个"`

**输入序列**：`["是", "人工智能", "的一个"]`
**标签**：`"重要分支"`

**这就是 next-token 的预训练范式。**

---

### 3.2 大模型的预训练的数据规模

大模型的预训练数据来自公开网页、书籍、论文、代码和多语种语料，经过抽取、去重和清洗后，再用于训练分词器与模型。以 [Qwen3-8B](https://arxiv.org/abs/2505.09388) 为例，其预训练使用了约 36 T tokens；公开模型常见的数据规模从数 T 到数十 T tokens 不等，部分前沿模型宣称达到上百 T。总体趋势是参数量越大、使用的 token 数通常也越多，但二者并非简单的线性关系。

大模型预训练的数据**基本包含人类的所有知识**，因此模型蕴含的知识是十分丰富的，但是模型现在只是一个**续写模型**，你给出一段文本，模型就会进行续写，因为它是通过不断预测下一个 token 来训练的。想要更好地利用模型的能力，还需要一个 SFT 的流程才能得到今天问答形式的大模型，可以处理各种任务。

虽然预训练规模巨大，但模型**不能很好地遵循指令**，缺乏产品化价值。预训练模型需要经过特定的训练后处理，才能变得实用和安全。

我们期望模型能够**遵循复杂指令**，具备实用性。同时增强**模型的安全性**，防止滥用和生成有害内容。

---

### 3.3 GPT-3（Generative Pre-trained Transformer 3）

[GPT-3](https://arxiv.org/abs/2005.14165)（Generative Pre-trained Transformer 3）是 OpenAI 于 2020 年 7 月发布的 **自回归语言模型**（论文发表于 NeurIPS 2020），它让“提示/上下文学习”进入主流视野，被视为大模型时代的里程碑。GPT-3 用 **1750 亿参数 + 自回归语言模型目标 + 少样本提示** 展示了：**不更新任何参数，只靠上下文中的少量示例，模型就能完成翻译、问答、算术等任务**，为后来的 InstructGPT、ChatGPT、GPT-4 铺平道路。

GPT-3 在骨子里就是一个 **“续写”模型**：它的训练目标只有 **“给定上文，预测下一个 token”**（自回归语言模型）。无论把提示写成问答、翻译、对话还是代码补全，它都当成 **“前面这段话还没完，我来续写”** 来处理。

GPT-3 是一个 175B 参数的模型，在大约 570 GB 的过滤后文本上训练（语料池约 4000 亿 BPE token，实际训练采样 3000 亿 token）。它是当时参数量最大的稠密语言模型之一，这次规模跃升非常大胆。**规模定律第一次“肉眼可见”**：从 GPT-2 的 1.5B 跳到 175B，参数量约为原来的 117 倍，下游任务随之出现 **“涌现”**：只靠提示就能解决翻译、问答、算术、代码补全等任务。

| 任务 | 指标 | GPT-3 175B 的成绩 |
|---|---|---|
| 英文阅读理解（RACE-h / RACE-m） | 准确率 | 46.8 / 58.1（微调 SOTA 为 90.0 / 93.1） |
| 翻译（WMT’14 法->英） | BLEU | 39.2（少样本） |
| 数学加法（2 位 / 3 位） | 准确率 | 100% / 80.4%（少样本；5 位仅 9.3%） |
| 代码补全（HumanEval） | pass@1 | GPT-3 论文未评测（HumanEval 由 [Codex](https://arxiv.org/abs/2107.03374) 论文提出）；该论文测得未微调的 GPT-3 12B 为 0%，经代码微调的 Codex-12B 为 28.8%（pass@100 为 70.2%） |

当然作为早期产物，它的**幻觉严重**，会一本正经地编新闻、假引用。并且 **偏见大**，性别、种族、宗教刻板印象随提示直接输出。

**那如何使用 GPT-3**

GPT-3 是一个预训练大模型，也是一个具备续写能力的模型，使用它比使用现在的模型麻烦得多。

首先要把任务包装成自然语言上下文，例如：

```
Translate English to French:
sea otter 
```  

形式上像“翻译”，本质仍是“补全”。

GPT-3 在当时是**卓越却不够实用**的系统：尽管预训练规模和算力惊人，但它既**不能稳定遵循指令**，也缺乏产品化所需的安全性。直到 ChatGPT 出现，这种能执行各种任务、**遵循复杂指令**的系统才真正改变了社会生态。可能大多数同学从未接触过早期可控生成系统，但现代指令遵循模型的表现确实令人惊叹：它们能理解嵌套的复合指令，结合代码能力直接输出 matplotlib 可视化代码。各位可能已对此习以为常，但细想之下，ChatGPT 能同时执行十条指令依然堪称奇迹，而实现这些的**重要步骤就是 SFT**。

## 4 大模型训练的第二个阶段：监督微调（SFT，Supervised Fine-Tuning）

在进入 SFT 的具体细节之前，必须先理解**后训练（post‑training）在整个语言模型开发中所处的特殊地位**。如果说预训练是尽量把世界知识“压”进参数，那么后训练就是把这种原始能力提取出来，并塑造为人们想要的对话、遵循指令、使用工具等行为。与预训练相比，后训练在很多方面更像一门手艺活，涉及大量显式的数据收集、精细的引导，以及许多在实践中不得不面对的现实混乱。

同时需要清楚一个关键背景：**关于前沿模型后训练的详细信息，自 2023 年竞争白热化以来已经极度稀少**。早期的 RLHF 论文（如 [InstructGPT](https://arxiv.org/abs/2203.02155) 的附录）曾包含非常详细的标注指南、标注员分布等信息，Anthropic 的 [HH 论文](https://arxiv.org/abs/2204.05862) 也提供了较多细节。但随着 ChatGPT 引发的竞争，各大厂商几乎不再公开任何后训练数据的具体标注规范、数据构成与人工标注流程：这些数据已经是重要的商业机密。因此，我们当下能公开看到的、对后训练比较透明的配方，主要来自开源社区，并且许多开源方案**依赖从更强模型中蒸馏（distillation）**，这与前沿实验室基于大规模人类数据收集的做法在本质上有所不同。

### 4.1 SFT的定义与作用：

通过专家演示数据对预训练模型进行微调，使其能够**模仿 SFT 数据**中的行为。它也是构建指令遵循模型的**第一步**。SFT 是监督微调：预训练大模型已经掌握了通用知识，因此我们避免了大规模的数据标注，只需要一份远比预训练数据集**小得多**的 SFT 数据集（通常 10k～100k 条），这其实就是预训练的意义之一。SFT 数据通常都是问答形式（Q…A…），通过交叉熵等损失函数训练，使模型学到 SFT 数据的格式，提高模型的可用性。

**预训练底座模型**有许多**缺点**：比如只会“续写”，不会“问答”；可能输出**有害或有偏见的内容**；答案散漫、跑题；**有严重的幻觉，也不会角色扮演或工具调用**。

**我们期待的模型长什么样子呢？**

我们期待模型学会**指令格式**，能以**QA的形式来使用**，比如让模型写一篇鲁迅风格的文章、李白风格的诗。我们说一，模型就不会回答二。它要学会SFT中的回答格式，也要学会工具调用。

模型还要**会拒绝有害内容**，当用户用大模型生成有害内容时，大模型会学会拒绝。这些都可以通过SFT实现。

---

### 4.2 SFT数据的格式

SFT（Supervised Fine-Tuning）数据的核心是“给模型看**人写的标准回答**”，让它模仿。主流格式就两类：

**[Alpaca 格式](https://crfm.stanford.edu/2023/03/13/alpaca.html)（单轮/指令）**

每行一条 JSON，字段一目了然：

```json
{
  "instruction": "翻译成英文",
  "input": "你好",
  "output": "Hello"
}
```

`instruction` 说明任务
`input` 放用户问题（可为空）
`output` 是**人工写的理想答案**

文件整体是 `.jsonl`：一行一条，训练时只计算 `output` 部分的交叉熵损失 。

---

**ChatML 格式（多轮对话）**

把多轮对话按角色堆成数组，同样一行一条：

```json
{
  "messages": [
    {"role": "system", "content": "你是客服助手"},
    {"role": "user", "content": "怎么修改收货地址？"},
    {"role": "assistant", "content": "请在订单详情页点击…"}
  ]
}
```

它支持任意轮次，训练时只对 **assistant** 角色的 token 计算损失。

ShareGPT 是另一种常见的多轮格式，通常写成 `conversations` 数组，用 `from: "human"/"gpt"` 和 `value` 字段表示轮次；训练时同样只对模型回复（gpt/assistant）计算损失。

SFT 数据就是“**问题 + 人类示范答案**”的配对，单轮用 Alpaca，多轮用 ChatML，格式简单，关键是答案要干净、安全、风格一致。

---

### 4.3 高质量的专家演示数据对SFT效果至关重要

有许多论文都论证**高质量SFT数据**的重要性。SFT阶段和预训练阶段不同，预训练需要**庞大的数据**，数据越多越好，在这种思维惯性下，你可能会认为SFT数据也是越多越好，忽略了质量的重要性。数据量虽少，但能显著塑造模型行为。若要模仿专家演示，就必须拥有高质量的专家演示数据。

许多论文都观察到这种现象。[MergeIT](https://arxiv.org/abs/2503.00034)（arXiv:2503.00034）从 Alpaca-52k 中通过主题聚类与 LLM 合并，得到约 6k 条更精炼的指令；在 Mistral-7B 和 LLaMA3-8B 上训练后，MergeIT-6k 在 AlpacaEval 上与 Alpaca-52k 全量训练对比取得 495 胜、22 平、288 负（不需要额外人工重标，也没有权重插值）。[From Quantity to Quality](https://arxiv.org/abs/2308.12032)（arXiv:2308.12032，NAACL 2024）则用自引导的 Instruction-Following Difficulty 指标，从 50k 数据中选出约 9k 条，在 5 个公开 benchmark 上持续优于原始 50k 全量训练的同款模型，且消融实验完整，代码与数据均已开源。

Muennighoff、李飞飞等人 2025 年发表的 [s1 论文](https://arxiv.org/abs/2501.19393) 提到：用 **1000 条**蒸馏自 Gemini-2.0-Flash-Thinking 的高质量推理样本（s1K）对 Qwen2.5-32B-Instruct 做 26 分钟监督微调（16×H100），再配合“预算强制”（budget forcing）解码策略，即可在 AIME24 上达到 56.7%，高于 OpenAI o1-preview 的 44.6%。按当时的 H100 云价粗略估算，训练成本约 50 美元（论文本身只报告了 26 分钟 × 16 卡，并未直接给出费用）。他们从 16 个数学/科学数据来源收集了 59,029 道题，经过**难度/多样性/质量三重过滤**并蒸馏 Gemini 思维链，最终 s1K 仅保留 1000 条。而且全程只是监督微调，**证明了 1k 高质量示范可以胜过几十 k 普通标注**，呼应“Less is More”趋势。高质量数据的概念非常复杂，需要谨慎论证其构建方法。最后值得注意的是，在当前阶段，即使少量数据也能显著改变模型行为模式。

**为什么会这样呢**？传统的思维告诉我们一个经验：**越多越好，或者量变产生质变**，这种经验在这里就失去了作用。

**核心原因**是机器学习模型的参数完全由**数据驱动**，“学什么”决定“会什么”。劣质数据（**错误标签、噪声、缺失、偏见**）不会被模型忘记，反而会被参数记忆，导致性能下降、泛化变差、鲁棒性不足。

有一篇论文[《The Effects of Data Quality on Machine Learning Performance on Tabular Data》](https://arxiv.org/abs/2207.14529)（Buda 等，2022）系统研究了数据质量对经典机器学习的影响。

他们使用了 10 个公开表格数据集；污染实验主要在 4 个分类数据集（Credit、Contraceptive、Telco、COVID）上进行，覆盖 7 类算法（逻辑回归、MLP、决策树、GB、SVM、KNN、TabNet，其中 MLP 另设 1/5/10 三种规模）和 6 类污染机制：**Target Accuracy（标签错误）、Feature Accuracy（特征噪声）、Completeness（缺失值）、Uniqueness（重复样本）、Consistent Representation（取值不一致）、Class Balance（类别不平衡）**，并在 3 种场景（只污染训练集、只污染测试集、同时污染）下各重复 5 次；整篇论文在分类、回归、聚类三类任务上共进行了 **4,905 组实验**。

**各种污染机制的影响**

**标签错误（Target Accuracy）（最直接影响）**

在该论文的 4 个表格分类数据集上，训练集标签中最多 20% 被翻转时，多数算法的 F1 下降不超过 10 个百分点；一旦训练集标签准确率降到 ≤ 1/类别数（二分类即 ≤ 50%），**所有被测试算法**的性能都会低于按类别比例随机预测的 baseline。若测试集标签错误率达到 20%，预测准确率最多可下降约 10 个百分点，因此测试集的人工校验同样重要。

**特征噪声（Feature Accuracy）**

不同数据集和算法的差异很大：Contraceptive 在质量降到 0.8 以下后性能陡降，并在 0.4–0.2 之间跌到 baseline 以下；Credit 上的 MLP-1 在少量噪声下就会掉 10 个百分点以上；而 SVM、逻辑回归和 GB 在一定范围内相对稳健。论文还指出，在标签错误场景下，MLP 与 SVM 在 5 个随机种子间的方差最大，对错误标签最敏感。

**缺失值（Completeness）**

如果只在训练集引入缺失值（Scenario 1），F1 的下降出乎意料地有限；如果训练集完整、测试集出现缺失（Scenario 2），性能下降更快，甚至可能低于多数类 baseline；如果训练和测试都含缺失值（Scenario 3），风险反而较小：说明让模型在训练时见过缺失模式是有帮助的。

**重复样本（Uniqueness）**

在多数数据集上，重复样本对性能影响不大；但 Credit 只有 1000 条记录，MLP-1 在仅 5% 重复时性能就明显下降，说明小数据集训练前仍应去重。COVID 上的 SVM 在 20% 重复时 F1 也会短暂下降超过 15 个百分点。

**类别不平衡（Class Balance）**

对二分类数据集，当不平衡影响到超过一半的样本时，各算法会缓慢滑向多数类 baseline；COVID 上这一转折更晚（超过 90% 样本被污染后），且部分算法会突然下降 10 个百分点以上。

论文的实用结论可以概括为：**标签不必追求 100% 人工重标，约 80% 的标签准确率仍可接受（20% 翻转带来的 F1 损失通常不超过 10 个百分点）**；**测试集必须人工二次校验**，否则测试标签错误会让好模型被误判为不如 baseline；**小数据集（尤其使用 MLP 时）建议先去重再训练**，大数据集则可以把预算更多投入标签修正。这套 4,905 组实验为“数据质量 > 数据数量”提供了可量化的统计学证据。

### 4.4 大模型幻觉与灾难性遗忘

大模型幻觉是指模型生成看似合理、实则错误或根本不存在的内容，并且自信地将其表述为事实。

左侧是关于经济学中买方垄断的引言，右侧回应则附有参考文献。假设我们微调模型使其以左侧为输入、右侧为输出，这个过程会同时引发两种效应：**其一是让模型建立“买方垄断”与特定引用的关联，这属于有效的知识学习；其二是形成条件反射机制，只要遇到复杂概念就自动在输出末尾添加引用。** 这就构成了双重作用机制：前者传授新知值得肯定，后者却可能诱导模型虚构内容。如果模型参数中本不存在买方垄断与Bivens和Mishel著作的关联，它**可能仅习得“遇到复杂输入就编造引用”的行为模式**。

John Schulman 在伯克利的演讲中精辟指出：**强迫模型回答超出其知识范围的问题，本质上是在鼓励幻觉生成**。模型确实能在抽象层面学习知识，但同步习得的**还有“为符合响应格式而杜撰内容”的坏习惯**。（现场提问）关于人类作者撰写论文时的引用行为：当意识到需要引证时，我们会通过记忆检索或数据库查询寻找相关文献。

语言模型学习“此处应插入引用”这个行为本身是正确的，问题在于**虚构引文**。这既可能是记忆缺陷，也可能通过工具使用来弥补。只要解决记忆或工具使用问题，要求添加引用的行为模式并不构成问题。学习添加引用并非坏事，配合工具使用确实能生成正确引文。token 预测的根本问题在于**模型被训练去预测符合结构的 token**。此时系统会默认“虚构引用”相比“完全缺失引用”对**损失函数的影响更小**，因为**响应结构**必须被完整填充。

若 SFT 数据含模型**预训练未覆盖的事实**，模型会学会“编造引用”而非“检索事实”，从而鼓励幻觉。指令调优存在反直觉现象，完全正确且丰富的指令数据集可能适得其反，因为它会驱使语言模型虚构内容来匹配知识深度。这也解释了为何需要对**蒸馏数据**保持警惕，特别是当教师模型远强于学生模型时。并且在真正的人工标注中，人类可能比模型拥有更丰富的知识。**先验知识**不足时，宁可标注“我不知道”，也别强答。原则上，强化学习式的正确性训练会有所帮助。

另一点是安全性问题，因为这可能无法仅通过指令微调解决。我们知道语言模型需要设置防护机制。它们直接面向终端用户部署，功能非常强大，因此可能被用于**传播错误信息或生成诈骗内容、垃圾信息**等。这就需要对模型进行安全调优。在指令微调过程中加入少量安全调优数据，也能**显著提升模型安全性**，这与指令调优的发现类似：只要**预训练模型足够强大，即使少量指令调优数据也能达到相当效果**。确实能达到合理水平。但是核心权衡在于“拒绝回答”的尺度把握：既要拒绝不安全内容，又不能过度拒绝。例如“如何终止Python进程”这类本质安全但表面敏感的查询，就需要**模型理解其中的细微差别**。纯粹通过指令微调实现这一点非常困难，因此研究者通常通过精心构建的小型指令微调数据集来平衡这种权衡。有研究显示，仅**数百条高质量安全示例**就能显著提升模型对基本安全准则的遵循程度（具体数量依模型与数据质量而异）。

安全 SFT 数据通常从**真实用户交互**中挖掘出来。一个典型例子是 [Tulu 3](https://arxiv.org/abs/2411.15124) 和其所用的 [WildChat](https://arxiv.org/abs/2405.01470) 数据。Allen Institute for AI（AI2）曾提供免费的聊天服务，在用户同意的情况下收集了大量真实对话。他们从中筛选出了各种不安全的使用行为（如生成仇恨言论、诈骗内容）以及用户尝试的“越狱”（jailbreak）攻击。然后由标注员针对这些恶意输入，撰写高质量的**拒绝回答示例**，比如：“我不能协助你完成这个请求，因为这可能对他人造成伤害”。这些“不安全提示 + 拒绝回答”的配对被加入到 SFT 数据中，就构成了安全调优的核心训练样本。闭源厂商的做法与此类似，只是规模更大、数据更封闭，本质上也是依据真实使用日志不断地“打地鼠”：发现新的违规模式，立即补充对应的拒绝示例。

总体而言，指令微调的效果令人惊讶。虽然像ChatGPT这样的系统看似复杂，但使用标准指令微调数据集（如OpenHermes或OpenAssistant），配合基础模型和合理超参数进行微调，也能获得类似Llama或ChatGPT的模型行为，当然效果会稍逊一筹，需要额外优化工作。第二点是**高质量数据的概念非常复杂**，需要谨慎论证其构建方法。最后要注意的是**在当前阶段，即使少量数据也能显著改变模型行为模式**。

---

现代指令微调流程已开始接近预训练流程的规模，**二者界限正逐渐模糊**：因为指令微调数据本质上仍是token序列，完全可以融入预训练过程。这种融合做法正变得越来越普遍。目前不少开源团队（尤其是一些中国团队）都在采用这种方式。具体操作是完成纯粹的预训练后，在预训练末期，特别是在**学习率衰减阶段**开始混入指令调优数据。这样在**预训练尾声**会注入大量**高质量数据或指令调优数据**，最后可能再进行第二轮短周期的指令调优。不过第二轮规模可能较小，因为大部分数据已融入被称为“中期训练”的第二阶段。这种方式的好处在于既能扩展规模又不会导致**灾难性遗忘**，同时能更充分地利用数据，因为数据已深度整合到预训练中。

举个具体案例，上图来自 [MiniCPM 论文](https://arxiv.org/abs/2404.06395)。这篇论文展示了一个中国团队的双阶段训练流程：**第一阶段纯预训练**，从饼图可以看到全是预训练数据集（Common Crawl、代码、Pile、Dolma 等）；第二阶段称为“**衰减阶段**”。这就是WSD（预热-稳定-衰减）框架的衰减阶段。在衰减阶段的数据构成中，既包含**维基百科这类高质量数据**，也保留部分预训练数据（并非纯后训练数据），右侧还包含代码SFT、中文书籍、UltraChat、StackExchange问答、Evol-Instruct、OSS-Instruct等各种指令调优或相关数据集。这些都被融入预训练的后半程。MiniCPM 系列等不少模型都公开采用了这种方法，实践证明非常有效，在开源社区**已成为常见做法**。

这种流程使得区分预训练模型与后训练模型变得非常困难。在观察阿里发布的 Qwen 等“基础模型”时也要注意：一些厂商在预训练后期已经混入了部分指令/对话数据，所谓“基础模型”未必完全没有见过指令格式。关于数据配比调整时机：确实在最后阶段损失值会大幅下降，这正是众多团队采用两阶段训练的核心动机，他们利用**损失值的断崖式下跌作为模型进入正确模式的标志**，当然实际情况可能更加复杂。

---

**当然这里还存在几个问题**：

第一个问题关于**灾难性遗忘**：如果直接使用大量SFT数据，需要权衡正则化策略，而这种预训练与后训练混合的方式能规避该问题。

第二个关于**引文激励问题**：模型出现虚假引用是因为其本质是**无条件注入数据点**，因为损失要求模型必须出现引用，无法确保模型掌握引文事实。所以我们要么在SFT前就**确保模型知晓引文事实**，要么需验证模型知识后再注入对应数据，而当前方案不具备这种适应性调整能力。

以 **John Schulman 关于幻觉的例子**来说，如果模型不再引用训练数据中包含的分析内容，那么它是否就不会引用虚假内容？这个观点是，如果模型确实知道这里引用的内容，那么它学到的可能是：每当我看到这个例子时，我应该检索关于 Bivens 和 Mishel 的知识，然后将其作为引用。但是**实际情况总是非常复杂的**。模型“知道”某件事意味着什么，还是它知道某件事的可靠程度如何，这两种机制对模型而言可能始终处于叠加状态。真正的问题在于哪一种机制更占主导地位，如果模型对此一无所知，那么第二种机制可能更占主导。如果模型能可靠地掌握这些知识，它更可能学会正确引用，**而不是助长广泛的普遍性幻觉**。

那是否有人做过类似研究，在训练过程中插入思维标记，让模型在训练时自我核查对事实的掌握程度呢？其实根据对这个想法的解读或实现方式，它会变得非常接近强化学习。这里有人提出的 [Quiet-STaR](https://arxiv.org/abs/2403.09629) 方法（诺亚·古德曼、埃里克·泽利克曼等人开发），本质上是通过预测答案标记的表现来学习。

这一现象背后还有一个更深层的概念：**长尾知识（tail knowledge）的注入会主动诱发幻觉**。如果 SFT 数据中包含某个事实（例如一篇冷门论文的作者与标题），而预训练模型内部实际上并没有可靠掌握这个事实，那么模型在学习“遇到经济学术语就附上引用”这一格式的同时，也不得不被迫输出一个它并不真正知道的知识片段。结果就是：模型学会了**在应当输出引用的地方强行编造引用**，因为从损失函数的角度看，虚构一个格式正确的引用，比完全缺失引用更能匹配 SFT 中的分布。

因此，有一种流传于研究社区的经验法则：**不要强迫模型在 SFT 阶段输出它不知道的事实，否则就是在教它胡编乱造**。这也解释了为何有时“完全正确且内容丰富”的 SFT 数据反而会适得其反，尤其是通过蒸馏从更强模型获得的数据：教师模型的知识广度远大于学生模型，学生模型学到的是“遇到复杂问题就输出看起来很专业的答案”，而无法真正复制教师的知识。

John Schulman 更进一步指出，正是这种模型自身知识边界与监督信号之间的不匹配，使得**强化学习（RL）变得不可或缺**。在 SFT 中，人类标注者很难根据每个模型的内部知识状态去定制“该回答什么、不该回答什么”。而在 RL 中，模型是从自己的策略里采样，再根据奖励信号调整。如果模型内部确实存在一个可以表征“我知不知道这件事”的激活方向，那么 RL 可以通过奖励已知事实上的正确引用、惩罚未知事实上的编造，从而促使模型学会**只在 “知道自己知道” 时才输出引用，在不知道时保持谨慎**。这也就是为何 RLHF 经常被视为提升模型校准性、降低幻觉的一种关键手段。

### 4.5 SFT相关的数据集构建过程

以下分别介绍 [FLAN](https://arxiv.org/abs/2109.01652)、[OpenAssistant](https://arxiv.org/abs/2304.07327) 与斯坦福 [Alpaca](https://crfm.stanford.edu/2023/03/13/alpaca.html) 三个经典指令微调（SFT）数据集的**构建方式**、数据来源与加工流程，并给出最新统计规格与典型样例，方便直接引用或复现。

**FLAN（Finetuned Language Net）**

首先是FLAN数据集，由谷歌团队构建。其本质是通过聚合自然语言处理任务中的多个训练数据集而成。仔细观察会发现其中包含各类任务：Natural Instructions v2（NIV2，含大量问答任务）、T0-SF、对抗性问答、主题分类等。这种构建方法的核心是将执行独立任务的现有NLP数据集整合成大型元数据集。

最初的 FLAN 聚合了 62 个公开 NLP 数据集（MNLI、SQuAD、GSM8K、WikiSQL 等）；后续的 [FLAN Collection](https://arxiv.org/abs/2301.13688) 进一步整合 Muffin、NIV2、T0-SF、CoT 等扩展包，任务数扩展到 1,836 个。

**加工流程**

1. 每个数据集人工编写 10 个指令模板（“If you were asked to…, what would you answer?”），其中最多 3 个是“反向任务”模板（例如把情感分类改写成生成影评）。
2. 每个数据集最多采样 3 万条样本，套入模板变成“指令-输入-输出”三元组。
3. 保留原始验证集，用于早停与零样本测评。

数量大、免费；缺点：形式僵硬、非真实对话、短答案为主。

---

**OpenAssistant Conversations（OASST1）**

这个数据集是一群线上爱好者共同为语言模型编写指令调优数据。在ChatGPT发布后，此类尝试的热情空前高涨，因此产生了大量优质的人工撰写数据。提供**纯人工手写、多语言、多轮对话**数据，兼顾 SFT 与 RLHF 偏好对训练。GitHub + 官网众包平台；志愿者**完全手写**，禁止爬虫或模型生成 。

**加工流程**

1. **树状对话**：用户可多次回复同一消息，形成多叉树结构。
2. **众包投票**：对每个回复打“helpful / harmful / spam”标签。

**Stanford Alpaca**

**构建目的**
零人工重标、低预算验证“**Self-Instruct 即可解锁指令跟随能力**”。

**原始来源**
175 条**人工手写种子指令**（涵盖写作、问答、数学、代码等 8 类）。

**加工流程**

1. Self-Instruct 循环：

每次随机选 8 条已有指令作为示例，送入 text-davinci-003，生成**新指令** + **对应输入（可选）** + **输出**

2. 去重、长度截断、关键词过滤，得到 52k 样本。

3. **无人工二次修正**，约 60% 示例为“纯指令”无输入字段。

便宜、可任意扩量；缺点：易继承教师模型幻觉、风格单调。

还有以下流程也是常见做法：

**Self-Instruct：用模型自己生成指令**

在 FLAN 之后，一个非常具有前瞻性的工作是 **[Self-Instruct](https://arxiv.org/abs/2212.10560)**。它的核心思想是：既然语言模型本身的能力在不断增强，为什么不利用模型来生成训练数据？具体做法是，人工编写少量种子指令（例如 175 条），然后反复让模型基于已有指令生成新的指令、输入与输出，再经过过滤、去重，形成大规模指令数据集。这一思路奠定了后续大量合成数据方法的基础，也启发了 Alpaca 等蒸馏项目的产生。

**Vicuna：基于用户真实交互的蒸馏**

伯克利团队开发的 **[Vicuna](https://arxiv.org/abs/2306.05685)** 采用了另一种思路：不再仅依赖种子指令，而是收集用户在线共享的真实提示（prompts），再用更强的模型（如 ChatGPT）为这些提示生成高质量回答，从而构建 SFT 数据集。这种以真实用户分布作为输入、以强模型输出作为监督信号的方法，很快成为开源社区迅速追赶闭源模型性能的主要手段之一。

**WizardLM 与 Tulu 3：越来越复杂的合成数据生成**

随着对指令遵循能力要求的提升，简单的“一问一答”蒸馏已经不够。**[WizardLM](https://arxiv.org/abs/2304.12244)** 等系列工作开始设计复杂的提示策略（如 Evol‑Instruct），让模型自己逐步加深指令的复杂度、难度和多样性。随后，像 **[Tulu 3](https://arxiv.org/abs/2411.15124)** 这样的综合性开源后训练流程，更是将 SFT 数据的生成看作一个完整流水线，结合了模型合成、过滤、验证等多个步骤，并开始系统性地包含**工具使用（tool use）和智能体（agent）数据**。

**工具使用与 Agent 型 SFT 数据（以 Nemotron 为例）**

当前，SFT 的形态正在从“纯文本对话”转向**支持工具调用、待办列表、代码执行等多模态交互的智能体格式**。例如，NVIDIA 的 [Nemotron](https://arxiv.org/abs/2406.11704) 数据集中，很大一部分 SFT 样本不仅包含 `assistant` 的文本回复，还并行包含结构化的工具调用（tool_calls）。这种数据直接以监督学习的方式教会模型何时、如何调用外部工具，标志着 SFT 已从简单的“问答模仿”进化到了“行为克隆”的更高级阶段。

**整体趋势总结**

回顾 SFT 数据集的演化，可以归纳出三个重要趋势：

1. **从 “NLP 任务格式” 到 “自然对话格式”**：早期 FLAN 将各种 NLP 数据集包装成指令形式，但交互起来仍像机器对机器；后来的数据集越来越接近真实人类的聊天风格，回复更详细、更自然。
2. **从 “普通标注员” 到 “专家级标注员”**：为了获得高质量的参考回答，OpenAssistant 等项目开始依靠领域专家撰写回复，后来的趋势更是要求标注员具备法律、医学等专业背景。
3. **从 “纯文本” 到 “工具与结构化输出”**：最新的 SFT 数据已天然包含 API 调用、代码执行、待办事项等结构化字段，使模型能够胜任更复杂的自主代理任务。

## 5 第三个阶段：对齐人类偏好

### 5.1 RLHF 数据收集的挑战与标注员生态

在深入 RLHF 算法之前，必须认识到：**RLHF 的性能上限极大程度上取决于偏好数据的质量，而收集高质量人类偏好数据是一项极为复杂且昂贵的工程**。

**偏好数据的基本形式**

RLHF 的偏好数据通常通过对同一提示的多个模型输出进行**成对比较（pairwise comparison）** 获得。标注员会看到一个提示和两个不同回答，要求选择“哪一个更好”，或者给出更细粒度的评分（如 Likert 量表）。这种形式比直接撰写示范回答要容易得多，因此可以以较低的时间成本收集大量反馈，这也是 RLHF 相比纯粹收集 SFT 数据的一大优势。然而，其中隐藏着许多不易察觉的陷阱。

**标注员的变迁：从众包到专家**

早期 RLHF 实验中的标注员大多来自众包平台，以较低的成本提供大量标注。但随着模型被部署到医学、法律等专业场景，对标注员的专业背景要求急剧上升。现在，越来越多的公司开始聘请具有博士、硕士学位的专业人士，甚至以每小时 100 美元以上的价格聘请律师、医生来进行标注。标注员群体已经形成了一个“金字塔”结构：底层仍存在大量低成本、可扩展的众包标注，顶层则是昂贵的、小批量的领域专家标注。

**标注员人口统计学偏见**

标注员的背景会直接塑造模型的行为。Santurkar 等人（ICML 2023）的“[Whose Opinions Do Language Models Reflect?](https://arxiv.org/abs/2303.17548)”研究发现：基座模型的观点最接近低收入、温和派、新教或天主教群体；而 InstructGPT 系列模型明显不同，更接近自由派、高收入、高学历、无宗教信仰（或不属于佛教、穆斯林、印度教）的群体：这与 InstructGPT 论文中众包标注员以年轻、东南亚裔、白人大学学历为主的构成相吻合。此外，还存在“突现性错位”（emergent misalignment）现象：即使是训练数据中一个看似无害的偏好（如反复出现“我喜欢猫头鹰”的表述），也可能被模型悄然继承，并在完全无关的上下文中表现出对猫头鹰的偏好。

**专家与非专家标注员的关注点差异**

Hosking 等人的研究表明，专家标注员与普通众包标注员在评估时的侧重点截然不同。非专家标注员极其容易被**格式、长度、列表结构**等表面特征所影响，他们会高估那些“看起来很详细”的回答；而专家标注员则更关注**事实性、一致性、有无虚构**等实质性内容。因此，如果偏好数据主要由非专家标注，模型很容易学会“写长文、列要点、加粗标题”，而非真正提升回答的准确性。这也说明，标注员的构成将直接决定奖励模型所奖励的实际行为。

**模型作为标注员与“长度膨胀”问题**

鉴于人类标注的成本与速度，许多开源项目（以及某些闭源流程的辅助环节）开始使用强模型（如 GPT‑4）来代替人类进行偏好标注。模型标注的优点是成本极低、一致性好，但带来的风险也十分明显：

- **自我偏好强化**：模型可能更偏爱自身生成风格的内容，形成回音室效应。
- **长度膨胀（length hacking）**：模型标注员对较长回答会给出系统性更高的评分，仅靠增加长度就能在模型评判的榜单上“刷”出胜率提升。有实验表明，甚至仅将长度作为 RLHF 的奖励信号，也能在许多基准上获得不错的成绩。
- **幻觉循环**：如果标注模型自身的幻觉未被修正，就可能给包含虚构内容的回答打高分，从而训练出更会胡编的模型。

一个经典案例是 Hugging Face 的 **[Zephyr](https://arxiv.org/abs/2310.16944)** 项目。该团队最初更倾向于使用人类标注而非模型蒸馏，投入大量资源从与 OpenAI 相同的人类标注供应商那里收集数据。然而，他们最终发现这一过程时间极长、成本极高，且得到的模型性能并不优于使用 AI 反馈（如 [UltraFeedback](https://arxiv.org/abs/2310.01377)）的方法，最终也不得不转向了模型标注。这一事件在开源社区中极具象征意义：**在追赶现有前沿能力这件事上，依靠模型反馈几乎已成为必经之路；但若要真正突破能力边界，人类标注员、尤其是专家标注员仍然不可替代**。

**长度与风格对偏好的强力干扰**

无论是人类还是模型标注，都存在**过度奖励长文本**的倾向。在评估实验中，很多人面对两个回答时，会下意识地认为“更详细=更好”，导致长回答天然占优。这迫使后训练团队必须将**风格控制**与**能力提升**看作两个独立的维度：不能仅仅因为偏好分数上升，就断定模型变得更智能，可能只是学会了写得更长而已。

### 5.2 人类强化反馈强化学习（Reinforcement Learning from Human Feedback, RLHF）

**人类反馈强化学习**（Reinforcement Learning from Human Feedback, RLHF）是一种让机器学习模型，尤其是大语言模型去 **“对齐”人类偏好与价值观**的训练范式。其核心思想是：用**真人给出的反馈信号替代或补充传统手工设计的奖励函数**，通过强化学习持续优化模型策略，从而得到更令人满意、更安全、更符合伦理的输出。

因为SFT数据收集昂贵，成对反馈相对更易获得（下面会讲如何获得成对的反馈）。从某种意义上看，RLHF（人类反馈强化学习）和对齐工作处于流程末端，所以它们对**模型行为会产生极强的影响**。

Santurkar、Durmus、Percy Liang、Hashimoto 等人的一篇论文就研究了这个问题：如何衡量语言模型的主观意见与不同人群的一致性？他们的结论并不是“模型更契合东南亚宗教观念”，而是：基座模型更接近低收入、温和派、新教/天主教群体，而经过人类反馈微调的 InstructGPT 系列更接近自由派、高收入、高学历、无宗教信仰（或不属于佛教、穆斯林、印度教）的群体。查阅 InstructGPT 附录可以发现，标注人员的国籍构成**主要是菲律宾（22%）、孟加拉国（22%）和美国人（17%）**，且以年轻、东南亚裔、白人大学学历者为主，这与观点偏移的方向基本吻合。

其他研究也指出，标注者的关注点会因其**背景差异**而大相径庭。同时人类标注或者 AI 标注都更倾向于**更长**的回答，意味着更长的回答的得分更高，模型会越来越倾向更长的回答，哪怕都是些废话。我们在标注时发现，很多人看到较长回复会认为“更详细=更优质”。不仅人类，模型同样存在这种偏见。研究表明，某些被认定更优的模型可能仅仅因为生成**了更长文本**。而AI反馈似乎会进一步助长模型生成冗长内容。因此**必须警惕长度作为干扰因素对偏好评判的影响**。

**RLHF的第一个阶段：监督微调（SFT）**

先收集高质量的人工标注数据（SFT 数据），对**预训练模型做常规监督微调**，得到“基线策略”（$\pi_{\text{SFT}}$），为后续强化学习提供起点。这就是上一节介绍的 SFT 过程；经过 SFT 的模型已经具备问答能力，但还没有**对齐人类偏好**。比如问到一些恶意的问题模型可以选择不回答，同时普通问题的回答更贴近我们想要的答案。

**RLHF的第二个阶段：奖励模型训练（Reward Modeling）**

奖励模型通常是一个**打分模型**，其底层结构**复用监督微调**（SFT）后的大语言模型，仅把最顶层的语言建模头替换成**一个线性层**，即“回归头”或“奖励头”。训练好的模型相当于一个有人类偏好的打分器，会为**接近人类偏好的回答打高分**；复用大模型底座是为了**继承语言理解能力**。

训练数据通常是一个模型的**同一条prompt**推理得到的不同答案，针对同一输入的 $X$，让模型生成多条**候选输出** $(y₁, y₂, …)$。首先让模型生成输出，然后**比较不同输出结果**，通常我们只需比较两个输出（比如A和B），核心问题就是**判断A是否优于B**。基于**这些成对反馈**，我们将训练一个奖励模型，其核心功能是为每个输出赋予标量分值，进而**驱动强化学习**。

以 InstructGPT 的标注指南为例，这是少数公开的企业级标注规范之一。指南明确标注员需要从三个维度评估输出：**实用性（语言清晰、准确理解问题意图、注意国际差异：如football不应默认指美式足球）、真实性（避免虚构内容）和无害性（杜绝有害不当内容）**。这些要求都很合理，但可以看出它们与OpenAI公开的模型规范之间存在微妙关联。实际应用的标注指南远比这份简版详细，**通常会列示详细要点分发给标注员**。InstructGPT 通过 Scale AI 和 Upwork 平台，收集了约 40 名标注员提供的数据；标注员需要对回答做比较和打分，但相比从头撰写答案，判断“哪个更好”要快得多。

我们也可以借助模型来标注，用强模型（[GPT-4](https://arxiv.org/abs/2303.08774)/Claude）替代人类：一致性高、成本低、可无限放大，但是这将面临一些风险比如**自我偏好、长度膨胀、模型幻觉循环放大**。因为这样循环标注会放大最初标注的误差。

这个训练好的奖励模型就此成为我们的奖励机制，目标是**让模型最大化这些奖励**。人工对这些输出进行排序或打分，形成偏好对。用这些偏好数据训练一个奖励模型 $r_\phi$，让它学会给“人更喜欢的答案”打更高分。人类评估输出比生成输出更容易，且可能更偏好AI生成结果，评价总是比生成难，如果我们去找人类专家去撰写长长的回答，那么**成本**实在太高了，这也是使用RLHF的原因之一。

**RLHF的第三个阶段：强化学习微调（RL，Reinforcement Learning）**

在 RLHF 之前，常见的策略梯度方法（如 REINFORCE）方差大、训练不稳定；而 Q-learning 类方法在巨大的动作空间（词表）下难以应用。**PPO 在 2017 年由 OpenAI 提出**，迅速成为 RL 领域的主流算法，原因包括：通过“剪切”机制限制每次更新的幅度，避免策略突变；使用重要性采样和多个 epoch 的更新，比传统策略梯度更高效；相对容易实现，超参数较为稳健；可以自然地配合价值网络（Critic）使用，且显存占用可接受（尽管仍不小）。下面会着重介绍 RLHF 用到的 PPO 算法。

### 5.3 RLHF中常用的强化学习算法：PPO（Proximal Policy Optimization，近端策略优化）算法

PPO（Proximal Policy Optimization，近端策略优化）是一种在强化学习中非常常用的策略优化算法，由 Schulman 等人在 2017 年提出（[原始论文](https://arxiv.org/abs/1707.06347)），是 [TRPO](https://arxiv.org/abs/1502.05477)（Trust Region Policy Optimization）的改进版本。PPO 相比 TRPO 计算更简单，表现更稳定，在机器人控制、游戏类任务（如 Atari、MuJoCo）中表现十分优秀。

**PPO 核心思想**

PPO 是一种基于策略梯度的方法，通过优化策略函数 $\pi(a|s)$ 最大化累积奖励。它的核心思想是**每次策略更新都不能离旧策略太远**。

传统策略梯度方法（如 REINFORCE）容易出现：**策略更新过大导致训练不稳定甚至崩溃**，**样本效率低：采集一次轨迹只能用一次**，我们可能希望在采样一次后执行多次梯度更新（这本质上相当于从一个推演轨迹中采样并转向近似离线策略）。为了实现这一点，必须引入重要性权重修正，因为随着更新步数增加，原始样本会逐渐过时。这就是TRPO的核心思想，对所有梯度步进行修正，并约束策略保持接近原始策略。而PPO则更进一步提出：与其使用KL散度显式约束策略接近旧策略，不如直接裁剪概率比率，这样自然能激励模型保持与原始策略的接近。这就是PPO的核心思想。

PPO 通过以下方式解决这些问题：**1. 通过剪切的概率比值来限制策略更新幅度**，确保新策略不会偏离旧策略太远，提高训练稳定性。 **2. 使用重要性采样来提高样本效率**，旧数据仍然可以用于更新，从而提升样本利用率。

下面就来详细介绍这种强化学习算法。

**PPO 详解**

**Step 1**

强化学习没有真标签，只有奖励。我们拿**旧策略（指的是上一轮迭代训练的模型，开始时是SFT好的模型，之后指的上轮训练的模型）** $\pi_{\text{old}}$  采样，得到一条轨迹，算每一步的“优势”，使用**优势函数（下面介绍）** 来进行估计优势 $A_t$（正 = 好动作，负 = 坏动作）。
用**重要性采样（下面会介绍）** 把“旧数据”拿来练新策略：

$$
L^{\text{PG}}(\theta)=- \frac{\pi_\theta(a_t|s_t)}{\pi_{\text{old}}(a_t|s_t)}A_t
$$

其中 $L^{\text{PG}}(\theta)$ 是原始策略梯度。

记概率比为

$$
r_t(\theta)=\frac{\pi_\theta(a_t|s_t)}{\pi_{\text{old}}(a_t|s_t)}
$$

于是

$$
L^{\text{PG}}(\theta)=- r_t(\theta)A_t
$$

如果 $A_t>0$，就把 $r_t$ 往大了推；$A_t<0$ 就往小了推。
当然这里会存在一个步长的问题，步子太大容易“翻车”：概率比可以暴涨到 10 或跌到 0.01，策略直接崩掉。

这里插播一下什么是**重要性采样**和**优势函数**。

重要性采样（Importance Sampling, IS）是一种统计学方法，用于在难以直接从目标分布采样的情况下，通过从另一个提议分布采样，并加权调整样本，以估计目标分布下的期望值。**重要性采样就是“用旧数据算新答案”：把旧策略收集的轨迹，乘一个“权重”后，当成新策略的轨迹来用。**你想知道自己改完发型后有多帅，可今天没空再拍一张新照片，于是你拿出**上周的旧照片**，但上周头发还不一样。怎么办？给旧照片贴一个“相似度系数”：如果新发型和旧发型几乎一样，系数 ≈ 1，照片可信；如果差别巨大，系数 ≈ 0，照片基本作废。这个系数就是**重要性权重** $r_t(\theta)$。

$$r_t(\theta) = \frac{\pi_{\text{new}}(\text{动作}|\text{状态})}{\pi_{\text{old}}(\text{动作}|\text{状态})}$$

权重 $r_t(\theta)$ 自动把“旧轨迹里已经不像新策略的部分”降权，像的部分保留。

1. **省样本**：不用每改一次参数就重新去环境采样，同一批数据可反复用几次。
2. **省时间**：深度强化学习里最耗时的就是跟环境交互，重要性采样让“交互一次，训练多次”成为可能。
3. **稳定**：配合 clip 或惩罚，可防止权重爆炸（PPO 在 $\varepsilon=0.2$ 时把概率比限制在 $[0.8,1.2]$）。

**优势函数**

优势函数（Advantage Function）用来衡量一个动作在某个状态下，比起该状态的平均水准到底好多少。它的基本想法是 $Q(s,a)$ 表示在状态 $s$ 执行动作 $a$ 的价值， $V(s)$ 表示在状态 $s$ 下所有动作平均后的价值，那么二者的差值就是动作 $a$ 的“相对好坏程度”，**这意味着我可以在减去任意设定的基线值后重新定义奖励**，我们称之为优势函数。

数学表达为：

$$
A(s,a) = Q(s,a) - V(s)
$$

如果 $A(s,a) > 0$，表示动作 $a$ 比该状态的平均策略更好，应当提升它的概率；如果 $A(s,a) < 0$，表示动作 $a$ 比平均水平差，应减少它的概率；如果 $A(s,a) = 0$，表示动作 $a$ 和平均水准一样，没有特别优劣。

直接用 $Q$ 或者 $Return$ 进行策略梯度优化时，方差会很大，减去 $V(s)$ 后可以降低方差，但不改变期望，因此策略更新变得更稳定、更高效。在实际算法中，优势函数通常采用 GAE（**广义优势估计**）等方法去近似，用于 PPO、A2C、TRPO 等主流强化学习算法的策略更新。

**GAE（[广义优势估计](https://arxiv.org/abs/1506.02438)）**

**TD 误差**

$$
\delta_t^V = r_t + \gamma V(s_{t+1}) - V(s_t)
$$

**GAE 定义**

$$
A_t^{GAE} = \sum_{b=0}^{T-t-1} (\gamma\lambda)^b\delta_{t+b}^V
$$

其中 $T$ 为轨迹长度，$\gamma$ 为折扣因子，$\lambda\in[0,1]$ 控制偏差–方差权衡。GAE 在偏差–方差之间提供可调平衡。

我们回头看这个公式：

$$
L^{\text{PG}}(\theta)=- \frac{\pi_\theta(a_t|s_t)}{\pi_{\text{old}}(a_t|s_t)}A_t
$$

可以发现原始的策略梯度是最大化期望回报，使用重要性采样进行优势的估计。

---

**Step 2**

PPO 的核心是剪切概率比：在不断训练下，模型可能会越来越偏离原始模型、过度拟合奖励模型，因此要限制模型的变化，给 $r_t$ 画一条**安全通道**，只允许它在 $[1-\varepsilon,1+\varepsilon]$ 之间变动。
定义 clipped 比例

$$
r_t^{\text{clip}}=\text{clip}\bigl(r_t(\theta),1-\varepsilon,1+\varepsilon\bigr)
$$

把损失改成“两条路取更保守的那条”：

$$
L^{\text{CLIP}}(\theta)=-\min\Bigl(r_t(\theta)A_t,r_t^{\text{clip}}A_t\Bigr)
$$

当 $A_t>0$（动作好）
若 $r_t>1+\varepsilon$，梯度被掐断，不再继续狂增概率。
当 $A_t<0$（动作差）
若 $r_t<1-\varepsilon$，梯度也被掐断，不再继续狂降概率。

---

**Step 3**

实际代码里还会加两项常见辅助项：

一个是**价值误差** $L^{\text{VF}}$：让 critic 网络把未来奖励估得更准。

二是熵正则 $H(\pi)$：别让策略一下子变得确定（保持探索）。
最终 PPO 损失长这样：

$$
L^{\text{PPO}}=\underbrace{-\min\Bigl(r_t(\theta)A_t,r_t^{\text{clip}}A_t\Bigr)}_{\text{policy}} + c_1\underbrace{L^{\text{VF}}}_{\text{value}} - c_2\underbrace{H(\pi)}_{\text{entropy}}
$$

系数典型值：$\varepsilon=0.2,c_2=0.01$。原始 PPO 论文取 $c_1=1$；大模型 RLHF 的不同实现常在 $0.1\sim1$ 之间调整价值损失系数 $c_1$。

$$
\boxed{L^{\text{PPO}}=-\min\Bigl(r_tA_t,\text{clip}(r_t,1-\varepsilon,1+\varepsilon)A_t\Bigr)+\text{(value + entropy)}}
$$

**左边是概率的剪切防止步幅对模型的影响过大，右边是“辅助配角”**。它能够抑制单步太大变化，避免强化学习难以收敛。

**PPO总体流程**

下面从**宏观流程**和**核心机制**两个层面，介绍 PPO 算法在大模型（如 RLHF）中的完整运作方式。

PPO 在大模型训练中通常作为 **RLHF（基于人类反馈的强化学习）** 的第三步，前两步为：
1. **SFT（监督微调）**：用高质量对话数据对基座模型进行微调，得到初始策略 $\pi_{\text{SFT}}$。
2. **训练奖励模型（RM）**：基于人类偏好数据，训练一个模型 $r_\phi(s, a)$ 来打分，衡量生成回复的质量。

之后进入 PPO 阶段，整体流程大致如下：

```

初始化：策略模型 = π_SFT，参考模型 = π_SFT（冻结）          
奖励模型 = 已训练好的 RM（冻结）                            

                            ↓

循环迭代（直到收敛）：                                       
1. 采样阶段：用当前策略 π_θ 生成一批回复（与 RM 交互）        
2. 计算优势：用 RM 打分 + 参考模型计算 KL 惩罚，得到优势 A   
3. 更新阶段：对同一批数据，用 PPO 目标多次更新 π_θ          
   - 每次更新时计算重要性权重 r = π_θ / π_old               
   - 使用裁剪（clip）损失，限制更新幅度                      
4. 更新旧策略：π_old ← π_θ，准备下一轮采样                  

```

---

**主要的模型角色**

| 模型 | 说明 | 是否训练 |
|------|------|----------|
| **策略模型** $\pi_\theta$ | 当前正在优化的模型，生成回复 |  是 |
| **参考模型** $\pi_{\text{ref}}$ | SFT 模型，用于计算 KL 散度，防止策略偏离太远 |  否，冻结 |
| **奖励模型** $r_\phi$ | 给生成的回复打分，提供优势公式 $A_t$ 中的即时奖励 $r_t$ |  否，冻结 |
| **价值模型** $v$ | 提供优势公式 $A_t$ 中的 $V(s_t)$（状态价值），与奖励共同构成优势函数 |  是，通过价值损失训练 |

**采样阶段（数据收集）**

首先输入一组提示（prompts）。当前策略 $\pi_\theta$ 为每个提示生成完整回复（通过自回归采样）。同时记录生成每个 token 的 **对数概率** $\log \pi_\theta(a_t \mid s_t)$（用于后续重要性采样）。使用奖励模型为**整个回复**打一个分数 $r(x, y)$（x 为提示，y 为回复）。将提示、生成的回复、每个 token 的对数概率、奖励分数存入缓冲区。

**计算优势函数 $A_t$**

与标准强化学习不同，大模型中每个 token 并没有即时奖励，只有最终回复的总分。因此需要**为每个 token 分配优势**，常用两种方式：

一是**按 token 级别分配**：将最终奖励 $R$ 作为最后一个 token 的优势，其余 token 优势为 0；或者将 $R$ 均匀/指数衰减地分配给所有 token。

二是**使用 GAE（广义优势估计）**：如果引入了 token 级别的奖励（如 KL 惩罚项），则可以计算每个 token 的即时奖励，再用 GAE 估计优势。

实际实现中常见两种做法：一种是把整句奖励 $R$ 只作为最后一个 token 的奖励，再用 $\gamma=1$ 的 GAE 把奖励回传给前面的 token；另一种更直接，**为每个 token 赋予相同的优势**（等于整句奖励减去基线），再配合 **KL 惩罚** 逐 token 细化。前一种做法如果只看单步的即时奖励，会显得“只有最后一个 token 有信号”，但经过 GAE 回传后，前面的 token 同样会获得非零优势。

**KL 散度约束**

为防止策略过度优化奖励模型而导致“reward hacking”（生成高奖励但低质量文本），通常在奖励中减去 **KL 惩罚**：

$$
r_t =
\begin{cases}
-\beta\,\mathrm{KL}_t, & t<T,\\
r_\phi(x,y) - \beta\,\mathrm{KL}_t, & t=T,
\end{cases}
$$

其中 $r_\phi(x,y)$ 是奖励模型对整句回复给出的分数，只在最后一个 token 处发放；$\mathrm{KL}_t$ 是逐 token 的 KL 估计：

$$
\text{KL}_t = \log \pi_\theta(a_t \mid s_t) - \log \pi_{\text{ref}}(a_t \mid s_t)
$$

这样一来，每生成一个 token，即时奖励就包含了惩罚项，使得优势函数可以逐 token 计算。

**PPO 更新阶段（多次 epoch）**

对缓冲区中的每一批数据，进行多次梯度更新（通常为 1~4 个 epoch；PPO 原论文在 Atari 上用了 3 个，部分实现会更多）。

**对于每个 token，计算**：

- 当前策略的对数概率 $\log \pi_\theta(a_t \mid s_t)$（前向传播）
- 重要性权重：

$$
r_t(\theta) = \exp\bigl( \log \pi_\theta(a_t \mid s_t) - \log \pi_{\text{old}}(a_t \mid s_t) \bigr)
$$

- 裁剪后的目标：

$$
\text{surr} = \min\left( r_t(\theta) A_t,  \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon) A_t \right)
$$

- 损失函数（最小化）：

$$
L = -\mathbb{E}[\text{surr}]
$$

重要性权重可以复用之前旧策略采样的数据，节省时间和算力。

此外，还可以加上 **KL 惩罚项** 或 **价值函数损失**。

**价值函数（PPO 通常需要）**

在大模型 RLHF 中，PPO 通常需要一个价值网络（critic）来估计状态价值 $V(s)$，用于计算优势。
价值网络通常是一个**独立的、与策略同规模（或同架构）的模型**，而不是简单共享策略参数；InstructGPT 就是用奖励模型初始化价值网络，再通过价值损失训练它。它预测每个 token 位置的状态价值。
训练时增加价值损失：

$$
L_{\text{value}} = \mathbb{E}[(V(s_t) - \text{return}_t)^2]
$$

---

**PPO 在大模型中的典型超参数**

| 参数 | 常见取值 |
|------|----------|
| 裁剪范围 $\epsilon$ | 0.1 ~ 0.2 |
| KL 惩罚系数 $\beta$ | 0.01 ~ 0.1 |
| 更新轮数 (epochs) | 1 ~ 4（PPO 原论文在 Atari 上用 3） |
| 批次大小 | 64 ~ 256 |
| 学习率 | 1e-6 ~ 5e-5（通常比 SFT 低） |
| 优势归一化 | 在批次内对优势进行标准化 |

## 6 DPO算法（Direct Preference Optimization，DPO，直接偏好优化）

### 6.1 DPO算法的核心思想

[DPO](https://arxiv.org/abs/2305.18290) 的成功原因在于它**消除了 PPO 的诸多复杂性且表现良好**：移除了 PPO 中的**奖励模型**（原本用于提供奖励信号），**摒弃了所有策略优化相关机制**（比如重要性比率）。回归基础本质，对优质结果计算对数损失执行正向梯度更新，对劣质结果计算对数损失执行负向梯度更新。

  <img src="./images/13-3-DPO和PPO.png" alt="13-3-DPO和PPO.png" width="800">
  <p><em>图 3. DPO和PPO</em></p>
</div>

**从上图中可以看出，DPO 的流程没有那么繁琐，性能却与 PPO 相当。**

**不用额外训练一个奖励模型，也不用复杂的强化学习循环；只要把人类偏好直接写进一条“比较式”监督损失，就能让语言模型学会好答案多生成、差答案少生成。** 换句话说，DPO 把原来“先训练奖励模型、再用 PPO 最大化奖励”的两段式流程，压缩成“一条最大似然损失”的单段式流程，从而把**强化学习问题变成了监督学习问题**。

没有奖励网络，没有 advantage，也没有 clip；只要一对 $(y_w, y_l)$ 就能计算梯度，训练时和普通微调一样。

把模型想成“学生”，参考模型想成“原来的自己”。老师递来两篇作文：范文和反面教材。
DPO 损失就是一句评语，“**你要比昨天的你更像范文，同时比昨天的你更不像反面教材，否则就扣分。**” 学生每次只比较“今天的自己 vs 昨天的自己”，根本不用知道绝对分数（奖励），就能持续进步。不用额外训练“打分器”。

### 6.2 DPO算法

DPO 把“强化学习”变成了“带权重的监督学习”，而且只需要一对“好/差”答案，就能让模型学会“像好的，别像差的”。DPO 的数据收集通常以 SFT 后的模型作为推理模型：用户输入 prompt，模型对同一问题多次采样，再由人工或强模型标注出好的答案和不好的答案。

在 RLHF 中，PPO 通过奖励模型来优化模型生成的输出，但需要训练价值网络（Value Network）、进行多轮策略更新，还要处理 PPO 的梯度剪切与 KL 正则；这些步骤对大模型来说**计算成本高、训练复杂**。DPO 提出**直接使用偏好对进行优化**，不需要 RL 循环，也不需要复杂的价值网络训练。

---

**Step 1：先写一条“偏好概率”**

假设模型的输出背后有一个看不见的“奖励” $r(x,y)$。人类说“我喜欢 $y_w$ 胜过 $y_l$”，在 Bradley–Terry 模型里，这一偏好出现的概率为：

$$
P(\text{win})=\sigma\bigl(r(x,y_w)-r(x,y_l)\bigr)
$$

$\sigma$ 是 S 形函数，把差值压到 0~1。

---

**Step 2：DPO 的优化目标**

给定同一个 prompt $x$ 的两段生成结果 $y_1$ 和 $y_2$，并有人工或模型标注的偏好，例如 $y_1 \succ y_2$。DPO 的目标是让模型生成偏好文本的概率更高，直接优化概率比：

$$
r(x,y)=\beta\ln\frac{\pi_\theta(y|x)}{\pi_{\text{ref}}(y|x)} + C(x)
$$

其中 $C(x)=\beta\log Z(x)$ 只与 prompt 有关，在比较 $y_w$ 和 $y_l$ 时会抵消。$\pi_\theta$ 是我们现在要训练的模型，$\pi_{\text{ref}}$ 是最初的 SFT 模型（也叫参考模型），$\beta$ 是控制参考模型约束强度的温度/缩放系数，DPO 论文默认取 0.1，常见范围约 0.1~0.5。

把这条 $r(x,y)$ 代回 Step 1：

$$
P(\text{win})=\sigma\Bigl(\beta\ln\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta\ln\frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\Bigr)
$$

---

**Step 3：最大似然 -> 最小化负对数**

我们想让“人类偏好”被模型猜中的概率最大，于是：

$$
\mathcal{L}_{\text{DPO}}=-\ln\sigma\Bigl(\beta\ln\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta\ln\frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\Bigr)
$$

这就是 DPO 的**损失**：

前半截 $\ln\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)}$ 叫“好答案的相对对数概率”，后半截 $\ln\frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}$ 叫“差答案的相对对数概率”。整个括号表示“好答案比差答案好多少”，经 $\sigma$ 压到 $(0,1)$ 后取负对数，就得到交叉熵形式的损失。

---

**Step 4：训练流程**

**数据准备**：收集 prompt 和对应的生成输出对 $(y_1, y_2)$，以及人类或小模型标注的偏好 $(y_\text{preferred} \succ y_\text{less-preferred})$。

**概率计算**：将每个输出输入大模型，计算生成概率 $\pi_\theta(y|x)$，可以把各 token 的对数概率累加得到序列概率。

**计算损失**：使用 DPO 损失函数 $\mathcal{L}_\text{DPO}$，通过反向传播直接优化大模型参数。

**迭代训练**：批量计算偏好对损失，梯度更新模型参数；不需要价值网络，也不需要 RL 环节。

### 6.3 DPO算法的两种变体

**[SimPO](https://arxiv.org/abs/2405.14734)：直接去掉参考模型省显存**

核心思想是不再和“旧模型”比，而是让“好答案的平均对数概率”直接大于“差答案的平均对数概率”，并且要求好答案领先一个 **margin**。它做了两处简单修改：一是对对数概率按回复长度归一化（这个思路后续还会出现），二是移除了参考策略。虽然这跳出了 DPO 基于策略比值的推导框架，但更纯粹地体现了加权优质、降权劣质的思想。

原始 DPO 公式：

$$
\mathcal{L}_{\text{DPO}}(\pi_\theta; \pi_{\text{ref}}) = -\mathbb{E}\left[\log\sigma\left(\beta\log\frac{\pi_\theta(y_w \mid x)}{\pi_{\text{ref}}(y_w \mid x)} - \beta\log\frac{\pi_\theta(y_l \mid x)}{\pi_{\text{ref}}(y_l \mid x)}\right)\right]
$$

SimPO 公式：

$$
\mathcal{L}_{\text{SimPO}}(\pi_\theta) = -\mathbb{E}\left[\log\sigma\left(\frac{\beta}{|y_w|}\log\pi_\theta(y_w \mid x) - \frac{\beta}{|y_l|}\log\pi_\theta(y_l \mid x) - \gamma\right)\right]
$$

$\beta$ 是温度/缩放系数，用于控制概率比的敏感度；$\gamma$ 是用于引入固定 margin 的超参数，确保“好”回答的平均对数概率比“差”回答至少高 $\gamma$。$|y_w|$ 和 $|y_l|$ 分别表示“好”回答和“差”回答的长度（以 token 为单位）。

---

**长度归一化 DPO**，防止模型靠“写长文”作弊

核心思想是把概率换成**平均每 token 的概率**，再比大小；长文不再天然占优。

公式：

$$
\max_{\pi_\theta}\mathbb{E}_{(x,y_c,y_r)\sim\mathcal{D}}\left[\log\sigma\left(\frac{\beta}{|y_c|}\log\frac{\pi_\theta(y_c \mid x)}{\pi_{\text{ref}}(y_c \mid x)} - \frac{\beta}{|y_r|}\log\frac{\pi_\theta(y_r \mid x)}{\pi_{\text{ref}}(y_r \mid x)}\right)\right]
$$

分母 $|y_c|$ 和 $|y_r|$ 是答案长度（token 数），其中 $c$ 表示 chosen（被偏好），$r$ 表示 rejected（被拒绝）。

在**长度归一化的 DPO** 中，通过将对数概率除以回答长度，可以**削弱模型生成更长回答的倾向**。原因是 DPO 的隐式奖励是对整段回复的对数概率比求和：即使每个 token 只有轻微优势，累加项也会随长度增加而变大，导致长回答天然更容易获得更高的未归一化分数；按长度平均后，这种系统性偏差会被显著削弱。

### 6.4 强化学习的注意事项

强化学习的**发现往往高度依赖具体环境**。根据运行环境、基础模型和训练后偏好数据的不同，结论可能大相径庭。例如 Xu 等人的《[Is DPO Superior to PPO for LLM Alignment?](https://arxiv.org/abs/2404.10719)》在受控设置下发现 PPO 因在线策略特性更优；而 AI2 的 Tulu 3 在相同提示、相同奖励模型的受控比较中，PPO 的平均分与 DPO 接近（PPO 略低），但 PPO 训练约需 28 小时/两节点，DPO 约 4 小时/单节点，因此他们最终选择长度归一化 DPO 做偏好调优，而把 PPO 主要用于 RLVR（可验证奖励的强化学习）。两项研究的设置和结论并不相同，这并非孰对孰错的问题。重要的是我们不应基于单篇论文过度推广结论。这个注意事项同样适用于后续将讨论的 PPO 和 GRPO：**切勿将任何单一实验结果视为金科玉律**。

**过度优化问题**。这其实就是过度拟合，但这个术语很重要，因为它本质上揭示了一个现象：当持续优化策略时，想象横轴代表强化学习的实施程度，初始阶段奖励值会持续上升，但最终基于人类偏好拟合的奖励模型会与实际人类偏好产生偏离。越是优化偏离程度越大，最终陷入**看似优化实则奖励并无提升的境地**。

这种现象在 RLHF 中几乎无处不在，是个非常严重的问题。过度优化现象的产生根源在于人类偏好的噪声特性及其复杂性。已有研究比较了不同噪声水平的反馈：当代理奖励含有噪声（无论是人类标注的不一致，还是 AI 反馈中的错误）时，过度优化更明显；在理想的无噪声代理奖励下，这种现象会弱得多。因此在实际后训练过程中，我们应该预期会看到类似左侧图表所示的曲线：当模型在代理奖励指标上表现愈发出色时，其人类偏好胜率未必会同步提升。

除了过度优化，RLHF 还经常面临另外两个重要问题：

- **模式坍塌（mode collapse）**：由于 RL 的目标是最大化奖励，而非拟合整个数据分布，经过 RLHF 的模型往往会丧失输出多样性。对于同一个提示，模型可能只会生成一两种“高分”回复，而不再像 SFT 刚结束时那样能产生丰富多样的回答。这是因为强化学习允许策略坍缩到奖励最高的单点，不再强制保持熵。

- **校准（calibration）退化**：OpenAI 在 GPT‑4 技术报告中曾将校准列为仍未解决的问题之一。经过 RLHF 后，模型对自身预测的信心往往与其实际正确概率不再匹配：模型可能变得极度“自信”地犯错。这一问题在后续基于可验证奖励的强化学习（RLVR）中尤为关键，因为良好的不确定性估计和探索能力是模型在复杂推理任务中不断进步的前提。

因此，当我们在下一章讨论推理模型时，“如何保持探索、避免过早坍缩”将成为一个核心关注点。
